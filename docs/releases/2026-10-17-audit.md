# 2026-10-17 — Application audit and fixes (0.17.1)

## Source

- Frontend: `c8d41b7`.
- Backend: `1a452eb`.
- No database migrations or mutations to production patient records.

## Fixed

- Web errors were using React Native Alert, which did not reliably display on web.
  Added queued accessible dialogs with cancel/destructive actions; native alerts remain native.
- Modal keyboard focus is trapped, background is inert, Escape closes only the top modal,
  and focus is restored. Removed blocking browser confirmations for document/chat deletion.
- Error boundary is inside the safe-area provider: its fallback no longer fails itself.
- Dynamics separates identical marker names by category and units. Unknown reference
  status is not painted as an abnormal measurement. Added a blood/urine regression case.
- AI chat uses the returned assistant response directly, avoiding a follow-up fetch that
  could report failure after a successful send. Input length matches the backend limit.
- Patient chat no longer receives physician-only instructions. Its prompt and UI clarify
  that chat sees the conversation, not automatically all stored documents/profile data.
- Upload panel scrolls on small screens; picker failures are visible and duplicate submits guarded.
- Profile accepts decimal commas and retains the user's birth date fallback; fields labelled.
- Patient-directory errors no longer appear as an empty directory. Late notes/AI responses
  are guarded against appearing under another selected patient.
- Schedule setup has a back button, scrollable settings and a fixed save action; removed
  the flexible standalone title that created excessive empty space above the settings.
- Article deletion asks for confirmation on native as well as web.
- Allowed-origin CORS preflight supports PUT (schedule API); untrusted origins remain blocked.

synthetic; no production DeepSeek call or real OCR/PDF upload was made. No real patient
record was deleted or edited. Actual deletion, native camera/sharing/printing, physical
iOS/Android keyboard/rubber-band behaviour, admin mutations and every doctor workflow
remain unverified. Patient-switch guards were code-reviewed/typechecked, not delay-tested
end-to-end. Live OCR accuracy needs a separate labelled-document benchmark.

## Remaining risks

- Four-digit PIN authentication needs an account-level abuse/lockout review; nginx's
  per-IP rate limit alone is not comprehensive brute-force protection.
- Contact and medical profile updates are separate requests, not atomic; partial save
  remains possible if the second request fails.
- SSH/HTTPS intermittently timed out during this audit, then recovered. No network or
  security configuration was changed; infrastructure reliability needs separate diagnosis.
